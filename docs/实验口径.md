# 实验口径

## 比较什么

本轮关注两个问题：知识如何接入客服 Agent，以及 Agent 能否给出正确、简短、自然的客户回复。

| 项目 | 已确定的口径 |
|---|---|
| 正式题集 | 前任 benchmark 的 test 50 题；各组使用同一批题 |
| 初始运行框架 | Hermes、Claude Code、DSH |
| 后续重点 | 固定 Hermes，对比原文件知识库、LLM-Wiki、Utopia |
| 无知识基线 | 不加载业务 Skill 和知识库；无需重复拆成多种知识后端 |
| 原配置 | 原 Skill 和旧知识库同时启用 |
| 模型 | 作答、评分均使用 AgentRouter 的 deepseek-v4-flash，high |
| 知识范围 | 将旧知识导入后端；未开展新业务知识补充 |
| 单题隔离 | 独立会话，关闭记忆和自动演化 |
| 运行记录 | 完整输出、工具轨迹、耗时、token、API/工具错误、实际后端与降级状态 |

评分侧可见参考答案和逐题规则；答题侧不可见。本次加入答题 prompt 的只是通用沟通要求，不包括评分权重、扣分规则或逐题答案。

旧规则对知识库引用有要求，无知识基线可能因此失分；不能把这种分差全归因于框架。

## 两套题不要混用

- **旧 benchmark**：train 120、val 30、test 50；本轮正式范围只取 test 50。
- **新 benchmark 120**：源于真实会话，但参考答案是按旧知识库另外编写的，没有逐题保留真实客服后续回答底稿，尚未经业务确认。未开展 120 题全量实验。
- 本仓库展示的 `hb-real-001` 是新题中的一次单题调试，不属于旧 test50 正式成绩。

## 接入与复现边界

Hermes 使用独立的 hermes-fork 配置与会话目录，源码维护在 [Hermes_Project](https://github.com/HappynessI/Hermes_Project)，本仓库不复制整套框架。Utopia 使用 dev 分支，本地 Ollama＋bge-m3 向量化；LLM-Wiki 使用编译后的 Markdown 知识。WorkBuddy 暂缓纳入。

原实验的 DSH 通过 npx 临时执行，不依赖全局安装。API 地址与认证由本机配置提供；已有端点不代表其他机器可直接访问。

完整端到端实验依赖私有题集、逐题规则、业务知识与部署。本仓库可直接复现的是**已判等级到总分的计算**，不是一键重跑全部 Agent。公开仓库不包含客户原始会话、内部会议纪要、知识库、密钥、完整模型请求或本机运行环境。

## 输出与指标

原 Skill 与实验 prompt 都要求三部分：建议回复、依据、下一步。前者给客户，后两者给客服内部使用。关注长度时只统计建议回复；后两部分允许保留必要细节。

必须分开报告：请求成功、运行完成、有效作答、业务质量。格式合格不等于业务正确，HTTP 200 也不等于获得有效答案。发现格式失败后，保留首次失败；修复重试另记，不覆盖原始结果。
