## 数据字段

每行是一个JSON对象：

- `record_id`：数据处理生成的记录编号，不是原始客户编号。
- `source_format`：`docx`、`markdown` 或 `csv`。
- `messages`：可见消息，含稳定的 `message_id`、`role`、`role_hint`、时间、脱敏正文及媒体缺失说明。消息ID中的 `v` 区分来源版本，`m` 表示原消息位置；重复来源里的相同消息只保留一次，不同版本追加的消息保留。
- `problem_types`：最终采用的类型数组。
- `classification`：采用哪个处理阶段、是否完成类型处理、是否需要补原文、类型确定性与诉求完整性。首次标注没有给出的独立确定性和完整性字段保留为 `null`。
- `intents`：各业务诉求及类型，分开列出客户正文证据和客服上下文证据；引文与对应脱敏消息一致。
- `information_gap_reason`：仅在信息不足的记录中给出未分类原因。

CSV原始说话人通常不明确，因此 `role=unknown` 与 `role_hint` 保留，不能将提示当作已确认说话人。`intents` 中证据采用的客户/客服身份是标注判断，也不覆盖原始角色信息。

## 可用范围

类型清洗已经完成；65条信息不足数据应排除在需要明确标签的任务之外。这是一批已标注的业务对话素材，尚未转化为最终评测题、训练集或人工业务确认的标准答案。类型明确不等于对话历史、图片、视频或客户具体诉求完整；制作Benchmark时仍须筛选题目节点和核验参考答案。

公开版移除了本地路径、原始说话人元数据、客户/客服编号、原始字段快照及调用缓存；对联系方式、长编号、已知昵称、详细地址和附带收件姓名进一步脱敏。保留业务产品、问题内容、消息顺序和分类证据。本地完整版本继续保存前两轮标注历史。

导出程序为 [export_dialogues.py](../../scripts/export_dialogues.py)，仅使用Python标准库，无API调用。以本地最终完整数据作为输入：

```bash
python3 scripts/export_dialogues.py --input /path/to/final_dialogues.jsonl --output-dir data/processed_dialogues
```
