# 产品类别六组补充实验

六组实验已完成：360份回答记录、360份评分记录，其中 359 份有可汇总的预览分。

比较完整原版（旧 prompt＋旧总 Skill＋旧知识库）与师兄产品版（分别接入新旧知识库），每种配置使用 LLM-Wiki 和 Utopia。固定实际模型 `doubao-seed-2-1-lite`、Rubric v3、60题、检索及迭代预算。没有使用师兄的补问材料进行训练或提供答案。

知识来源和编译内容复用上次冻结快照；Utopia 复用已冻结的两个独立知识库。仅适配两种只读知识入口与最终正文保存方式，未改写原版和师兄版业务规则。

主比较为答题前选定的12个产品功能、选型、适配及基础使用问题；其余48题记录技术故障、实时业务和混合风险的处理，不用其总分判定产品类别更新是否有效。题目仍为 dev40＋calibration20，全部标准待业务确认；成绩是同模型评分预览。

## 结果解释

本轮不能认定师兄产品版已经稳定优于完整原版。Wiki 接入的产品题均分有所提高，Utopia 接入的产品题均分下降；两种后端都仍有严重错误或无有效答复。以下结论只描述这批开发题的评分预览。

1. **保持旧知识库时，prompt＋总 Skill 的修改呈现不同效果。** Wiki 从47.50升至58.00，变化为+10.50分，但同题仅5胜、7负；Utopia 从63.58降至48.83，变化为−14.75分，同题5胜、1平、6负。Wiki 三组都有4道严重封顶题，均分提高并未消除这些问题。
2. **师兄版接入新库，未提高这12道产品题的均分。** Wiki 从58.00变为56.25；Utopia 从48.83变为47.00。新旧库的13份产品资料内容完全相同，本次知识库更新主要涉及处理流程，不能期待它直接补充新的产品事实。
3. **Utopia 下的检索停止问题明显影响产品题结果。** 原版2/12题耗尽预算，其中1题未形成有效正文；师兄旧库和新库均为5/12题耗尽预算，分别有3题、5题未形成有效正文。这些失败全部纳入评分；有效正文也不代表业务内容正确。
4. **新知识库的收益主要体现在其余48道流程题。** 师兄版更新知识库后，Wiki 从49.44升至90.15，Utopia 从61.75升至89.23。全60题的新库成绩为83.37和80.78，但不能用全题均分说明师兄对产品咨询的更新已经通过验收。

产品题六项配对比较的题目重采样95%区间均跨过0。样本只有12题，且已发现个别裁决存在语义问题，因此不作稳定优劣或统计显著性的结论；这些区间也不代表未来客户总体。

## 根据本轮结果应优先处理什么

- **先复核产品主比较的业务事实与评分。** 区分可直接回答、条件回答和必须澄清；不要把“资料不足时追问”解释成所有推荐问题都必须追问。对已明确的事实冲突，应正确识别和封顶。下面的人工抽查记录给出了具体案例。
- **为检索过程增加可执行的停止和交付规则。** 已取得充分依据就生成本轮回复；重复同一检索且没有新增信息时，明确具体知识缺口，并给当前客服核验建议。达到迭代边界前仍应交付三部分正文。这需要在下一轮单独验证，不能把本轮失败重跑后混入当前成绩。
- **补全资料后再下型号功能结论。** 本轮出现将“检索片段没有记录”误写成型号未支持功能、引用不存在文件的情况。应读取与结论有关的型号章节，区分片段未覆盖与文档明确否定；资料冲突或不足时保留未知。
- **保留按业务意图读取新知识库的方式。** 新库对其他流程题的改善值得保留；产品咨询优先读取产品资料和本轮必要边界，实时交易与故障流程在触发后再接入。师兄材料中的AI补问没有在本轮训练或充当评分真值，其数据增补效果需要另外评估。

不建议据这批结果直接替换现有配置。先处理检索超限和评分口径问题，再在独立来源的真实产品题上复测，才能判断师兄产品版是否满足“比原版更好”的要求。

## 交付与核验状态

- 六组各60题，合计360份回答记录和360份评分记录；其中359份有预览分，1份裁决无效。产品主比较72份评分全部有效。
- 唯一无效裁决为 `O_W / hb-v3-010`，连续三次字段校验失败，原因包括缺少当前目标、维度ID不符合要求。它只影响其他场景及全题汇总，未补成0分，也未通过额外重跑消除。
- 全部360份实际答题请求已核对对应的 prompt 和 Skill；原始来源、候选知识库和两套 prompt、Skill 均保持实验开始时的内容。
- 全部记录到的实际模型返回均为 `doubao-seed-2-1-lite`。本轮沿用上一轮模型，不能把本轮结果写成豆包 Turbo 的成绩。
- 12份评分锚点的6组好坏次序全部通过；答题进程读取评分标准文件被实际隔离机制拒绝。
- Utopia 作答结束时，54份文档和333个分块均完成抽取与向量化，无进行中或失败任务。
- 文档、运行及模型初评已完成；逐题标准的业务确认、全部回答的人工语义复核和独立正式测试尚未完成。

## 比较边界

原版与师兄旧库的配对主要检查 prompt＋Skill 更新；师兄新旧库的配对检查知识流程更新；师兄新库相对原版同时包含两类变化。两个后端都保留原生检索过程，不能把差异解释为纯检索算法差异。

程序完成、格式合格、有效正文和业务质量分别记录。预算耗尽属于被测结果，不通过重跑消除；接口或检索失败保留诊断。缺乏权威证据的题目按 needs_review 处理并单列评分覆盖，不把自动评分当成正式业务验收。
