## hb-v3-001

换地点不等于换Wi-Fi

预览分：89.0；程序完成：True；检索降级：False；预算耗尽：False。

### 建议回复（可直接发给客户）

"换了地方之后连不上，最常见的原因就是换了新的 Wi-Fi 网络，设备里存的还是原来那套，所以连不上。您先告诉我一下：**新地方用的 Wi-Fi 和之前家里的是同一个吗？**
另外这台设备是什么型号（比如机身底部的标签名称）？我按对应型号的换网方式带您重新配一下。**先不用动设备，也不要解绑、删除设备或换绑定账号**，等我确认好步骤再带您操作，避免资料受影响。"

### 依据

**会话事实**
- 客户：换了个地方用（会话最新一条）。
- 客户此前疑问：红灯不会闪烁；连一早上没连上，怀疑与网络信号有关。
- 客服上一轮已提醒：重新联网需要重置，不要解绑/删设备/换绑账号/卸载 App。
- 关键未知：新地点 Wi-Fi 是否与原网络一致、设备具体型号、当前 App 显示是离线还是无画面、插电灯态是否观察过（已问但未回复）。

**知识库事实**
- "换地点"不等于"换 Wi-Fi"，未确认换网时先问网络是否变化；已确认换网则补型号后再给对应换网步骤（`20_intents__02_connection_pairing.md` 4. 换地点、换Wi-Fi）。
- 灯态只作型号/阶段相关的观察，不能直接确诊；旧"红灯闪烁=配网"类教程缺型号/版本适用依据，需内部技术确认后才能对对应设备使用，不能当通用步骤发给客户（`20_intents__02_connection_pairing.md` 5. 标准回答规则、6. 换 Wi-Fi 后设备离线）。
- 重置/换网前保留原绑定、不删设备不换账号、操作前说明数据风险（同上文档 4. 换地点、换Wi-Fi 风险段）。
- 追问规则：只补影响当前处理的信息；已提供/已尝试过的条件不重复索取（`00_global__answer_style_and_escalation.md` 需要追问）。

**待核验项**
- 新地点 Wi-Fi 名称/频段（2.4G/5G）是否与原网络不同。
- 设备具体型号（旧"RESET 10 秒红灯闪烁"教程的适用范围需内部技术确认）。

### 下一步

1. **等客户回复两点**：①新 Wi-Fi 是否和原来同一个；②设备型号。这是决定走"换网重配"还是"离线排查"的分叉，不要先一步发重置教程。
2. **若客户说 Wi-Fi 换了**：不要直接发"RESET 10 秒红灯闪烁后扫码"这条旧教程——它缺型号/版本依据。先在内部查该型号的适用换网流程（或请内部技术/产品同事确认该型号是否适用此教程），确认后再带客户操作；操作前再次提醒不解绑、不删设备、不换账号。
3. **若客户说 Wi-Fi 没变**：转入"已绑定后离线"分支，按顺序看供电（适配器/插电灯态）→ 网络环境，不再按换网重配。
4. **若客户回复型号后内部也查不到适用换网步骤**：带型号、App 版本、灯态描述和已尝试记录（重启插头一早上未连上、换地点）交内部技术协助，不要让客户反复重置试探。
5. 注意：客户上一轮被问过"插电瞬间红灯是否亮一下再熄灭"还没回答，如本轮客户顺带回答了可直接复用，不必再单独追一次。

### 模型评分摘要

答案整体符合换地点配网场景的处理要求，正确区分了换地点与换Wi-Fi的差异，保留了绑定保护要求，内部分支指引清晰；仅客户草稿额外索要设备型号属于可延后的冗余内容，小幅调整后即可发送。

客户草稿可发送性：`minor_edit`；数值评分和各维度理由见同组JSONL。

## hb-v3-002

在线但画面卡90%

预览分：100；程序完成：True；检索降级：False；预算耗尽：False。

### 建议回复（可直接发给客户）

您好，设备显示在线、但画面一直卡在 90%，这个我们先按"画面加载"这一项来处理，不用重新配网。

麻烦您先看一下当前 App 的版本号（一般在 App"我的/设置"页面里），报给我一下。另外想确认：之前能正常打开画面吗，是从什么时候开始卡的？

我这边先帮您核对一下版本和适配情况，您回复后我们再继续往下看。

### 依据

**会话事实**
- 客户自述：APP 显示设备"在线"，但进入实时画面后视频一直卡在 90%（截图仅为文字描述，原图未提供，不能凭截图文字做画面诊断）。
- 截图文字描述：海马爸比二代焕新版 APP 界面。

**知识事实**
- 型号可映射为"海马爸比宝宝看护器2代焕新版"（`aliases.yaml`，别名"二代焕新版/焕新版"），属于实时看护器实时视频链路，不是录像回放问题（录像/SD 卡另走功能使用分支 04）。
- "在线但无画面或卡加载"处理流程：复用在线事实，不重复问"是否在线"，也不按离线引导重配；本轮从 App 状态选一个低风险确认（如 App 版本）；客服内部核对版本与画面路径适用性，**没有当前日志/服务状态时不归因服务器或硬件**（`20_intents__02_connection_pairing.md` §4"在线但无画面或卡加载"）。
- 反馈后的分支：确认有适用版本方案再指导更新；仍失败再核固件与具体网络环境（`20_intents__02_connection_pairing.md` §6 常见问答）。
- 缺失图片/视频先承认不可见，不给确定画面诊断（`00_global__answer_style_and_escalation.md` 需要追问）。

**待核验**
- App 当前版本号、之前是否正常、开始异常的时间点——客户尚未提供。
- 当前是否有适用的 App/固件更新及前置条件——需客服内部核对后再决定，不在本轮承诺。

### 下一步

1. **等客户回复 App 版本号 + 异常开始时间**（一次补齐，不再重复索取已确认的"在线"状态）。
2. 客服内部核对：该 App 版本对 2代焕新版实时画面是否有已知适配问题或适用更新；**不要**在无日志/服务状态证据下直接归因为"服务器问题"或"设备硬件故障"。
3. 分支：
   - 若存在适用 App/固件更新方案 → 核实前置条件后，再分轮指导客户更新（不要一次性发整套重启/重置教程）。
   - 若客户反馈后仍卡 90%、或需日志判读 → 停止重复步骤，整理型号（2代焕新版）、现象（在线但实时视频卡 90%）、已尝试记录，交内部技术岗位判读日志，由技术返回必要判断后再回复客户；不引导客户重置、删绑定或格式化卡。

### 模型评分摘要

答案正确复用已知的设备在线、二代焕新版信息，选择询问APP版本这一低风险画面加载确认项，内部明确区分在线与视频加载失败的边界，标注所有待核验的未知条件，无事实错误或无依据承诺，客户草稿可直接发送。

客户草稿可发送性：`send_as_is`；数值评分和各维度理由见同组JSONL。

## hb-v3-003

询问发哪家快递

预览分：89.0；程序完成：True；检索降级：False；预算耗尽：False。

### 建议回复（可直接发给客户）

您好，我们不同渠道和地区合作的快递可能会有所不同。请问您是已经下单了吗？如果已经下单，我帮您查一下这单实际发的是哪家快递；如果还没下单，我帮您核实一下对应渠道和收货地的配送安排，再回复您。

### 依据

- **会话已知**：客户只问"发什么快递"，未提供订单号、下单状态、收货地区或商品信息；本轮可见会话无订单卡、历史通知或图片。
- **知识库事实**：
  - `20_intents__06_order_logistics.md` 第4节"各场景的核验分支"——"发哪家快递"场景：本轮核验项为"对应渠道/区域配送规则或该单实际承运商"；结果后动作是"未下单说明核实规则，已下单答真实承运商；不能保证所有地区固定一家"。
  - 同文件第8节"需要追问的情况"：只补订单/售后定位、包裹方向、物品或核验必须的区域；不重复索取已有信息。
  - 同文件第5节：先区分商家寄出与客户寄回，再区分购买、补寄和检测返还；没有实时状态是正常条件，不假设仓储或快递接口已接入。
  - README 与 `00_global__brand_and_scope.md`：助手无订单、物流、库存实时查询接口，仅提供只读知识。

### 下一步

1. **等待客户回复"已下单/未下单"及收货地区**（如有订单号可一并索取）。
2. **若客户回复已下单**：当前客服在有权限的订单/物流系统中查询该单实际承运商；若无权限，请内部履约/配送负责岗位返回该单实际承运商与当前出库状态，再据实回复客户。
3. **若客户回复未下单**：当前客服核实对应渠道（店铺/活动页）与收货地的配送规则；权限不足时请内部履约岗位返回该渠道、该地区的实际承运安排，不要按统一口径承诺固定某家快递。
4. **注意**：不要承诺"固定发某家快递"或具体送达时效；若客户同时催发货或反映等待超时，转同文件第4节"购买订单催发"分支处理。

### 模型评分摘要

答案整体方向正确，内部核验分支清楚，未承诺固定快递；客户草稿可直接使用，但可微调为更直接的“我先核对”语气。

客户草稿可发送性：`minor_edit`；数值评分和各维度理由见同组JSONL。

## hb-v3-004

设备转向引发隐私疑虑

预览分：79.0；程序完成：True；检索降级：False；预算耗尽：False。

### 建议回复（可直接发给客户）

先别着急，非常理解您的担心。宝宝休息时发现镜头方向自己变了，确实会让人不安。我们先一起确认两件事：

1. 您可以打开 APP，进入这台设备的设置，看一下「设备共享」里是否有除了您之外的其他账号（家人、朋友或不认识的账号）？有的话请把账号名称发给我，先不要自己删除。
2. 另外，您这台机器是几代的看护器？部分型号有「云台跟随」功能，宝宝在画面里移动时镜头会自动转过去，这种情况和被远程控制是两回事。

您先看一下共享列表和型号，我这边同时帮您核对一下设备记录。如果确实有异常账号或者镜头频繁无故转动，我们再进一步排查。

### 依据

**会话已知**
- 客户称清晨六点多家人睡觉时，看护器镜头方向自行偏离宝宝，并感觉"被人控制"。来源为客户当前消息，无截图/录像佐证，具体型号、账号共享情况未知。

**知识库事实**
- 海马爸比看护器 4 代支持「云台转动/跟随」，可根据宝宝移动自动调整镜头方向；实际跟随效果受网络、安装位置、环境遮挡和宝宝移动速度影响（`10_products__monitor__models__hb_monitor_4.md` 四代专项问答口径）。
- 设备共享路径：主账号设备共享中「+添加共享」，输入家人的海马爸比账号；共享不等于主账号被外人控制，需核对共享列表（`20_intents__02_connection_pairing.md` §6 常见问答）。
- 账号归属异常、需日志判断或基础排查无效时，应交内部技术/账号负责岗位，不向客户索取密码、不绕过认证（`20_intents__02_connection_pairing.md` §8–9；`00_global__customer_service_boundaries.md` 升级人工）。
- 重置、删除设备、换绑等属于不可逆操作，需先保护资料并说明风险，不在本轮直接建议（`00_global__answer_style_and_escalation.md` 数据风险提醒）。

**待核验**
- 设备型号、是否开启云台跟随/自动巡航、共享列表中是否有陌生账号、清晨六点前后是否有 APP 操作记录或登录提醒——均需客户反馈或客服内部渠道核验。

### 下一步

1. **等客户回传**：共享列表截图/账号名称 + 设备型号。这是当前分叉点：
   - 若共享列表出现陌生账号 → 走账号安全分支：建议客户修改账号密码、解除可疑共享，并把设备型号、账号、异常时间交接内部账号/技术岗位确认是否有非法访问；不要让客户自行重置设备。
   - 若只有家人共享 → 大概率是云台跟随或家人远程操作，按型号引导核对跟随开关和家人 APP 操作记录。
   - 若没有任何共享、镜头仍自行转动 → 走 04 功能使用 / 05 售后检测分支，带型号、现象时间、尝试记录交内部技术判读日志，不重复让客户反复试。
2. **客服可并行做**：用自己有权限的渠道查该客户账号下的设备型号和绑定记录（如有订单/CRM 权限），避免让客户重复提供订单号。权限不足时找内部账号/技术岗位，交接"清晨镜头自行转动 + 客户怀疑被控制 + 待确认共享列表"这三点即可。
3. **本轮不要做**：不要直接建议客户恢复出厂设置或删除设备（涉数据/绑定风险），也不要在未核实前就说"一定是被黑客控制"或"一定是云台跟随误触发"。

### 模型评分摘要

答案整体方向正确，自然回应了客户对设备被控制的担忧，内部支持清晰区分了客户观察与入侵结论，明确了待核验项和后续技术交接路径，未编造业务状态或做出极端断言；主要不足是客户草稿同时提出两个独立确认项，未在当前轮给出即时的基础隐私保护建议，精简后即可发送。

客户草稿可发送性：`minor_edit`；数值评分和各维度理由见同组JSONL。
