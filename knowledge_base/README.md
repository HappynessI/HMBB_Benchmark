# 海马爸比一线客服支持知识库（候选版）

沿用产品事实层、客服意图层、全局规则层和历史归档结构。当前用户是粘贴会话的一线客服；助手提供客户草稿、依据与客服下一步，由人工确认和执行。

候选流程更新于2026-10-10。产品事实继续沿用原知识快照，本轮未重新验证全部参数与政策。流程示例是设计示例，不是唯一话术或业务执行记录。没有订单、物流、退款、库存、活动、日志分析或业务操作接口。

## 使用原则

1. 先确定客户当前诉求与已知条件，通常推进一个必要问题或阶段。情绪承接按实际语境，安全风险先保护。
2. 产品或操作依赖型号才查别名与对应产品；`ambiguous_aliases`优先阻止强行归一。
3. 按问题选对应意图分支，已知不重问、失败步骤不机械重复。长教程只在前置条件明确或客户请求完整指南时使用。
4. 实时业务由当前客服核验，权限不足找内部负责岗位。待执行建议和真实执行结果分开。
5. 全局边界约束具体操作；风险与数据保护写在相关操作前。原始敏感日志只由客户内部分析，助手使用必要返回结果。
6. 只读manifest的`active_documents`。`_archive/`保留原文追溯，不是作答依据；维护报告和场景检查在知识目录外，不参与检索。

## 产品事实入口

保留`10_products/monitor/monitor_overview.md`、`monitor_specs_matrix.md`、`monitor_feature_matrix.yaml`、`monitor_compatibility_matrix.yaml`及`models/`、`10_products/ecommerce/`。产品层本轮内容未改；原价不是现价，原支持项不是医疗有效性或100%效果。原别名中的泛称歧义在别名表和检索规则标出。

## 检索顺序

当前诉求→必要意图分支→有需要时别名/产品/矩阵→相关全局边界→具体核验或内部协助。不是每次按所有文件完整遍历。见[检索与冲突规则](retrieval_rules.md)、[风格](00_global/answer_style_and_escalation.md)和[边界](00_global/customer_service_boundaries.md)。

## 运行入口与状态

本目录是候选知识源，不能因文件更新就认为既有Agent已切换。候选总Skill默认入口为工作目录中的`./input/knowledge_base/`；运行方需明确把本目录的active_documents放到该入口，并配套候选system prompt。

旧文件实验从Skill内`references/knowledge_base/`读取；已有LLM-Wiki/Utopia使用另行导入的快照，不会自动同步。候选导入必须独立建库并复核原文映射；本轮未更新这些后端或业务接口。入口准备与结构读取验证不等于模型效果验证。

## 禁止事项

- 不读取benchmark逐题标准、参考答案、权重或评分锚点，不把未来测试来源写入知识。
- 不由历史对话、自动通知或订单卡片确定当前状态、正式规则或缺失画面。
- 不假定已接ERP、工单或日志分析，不声称助手已代查代办，不保证时限或交易结果。
- 不跳过必要前置与资料保护，不在已失败阶段反复试错。
- 不把旧保修、专用重置或菜单的未明适用范围擅自变成统一政策；冲突与缺失交业务确认。
