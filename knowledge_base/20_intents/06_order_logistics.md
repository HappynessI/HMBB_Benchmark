# 订单与物流

## 1. 适用范围

购买发货、补寄配件/更换设备、物流停滞、运单查不到、客户寄回收件、可售与发货安排。只有业务核验方法，不包含实时订单、库存或承运数据。

## 2. 用户常见说法

什么时候发、补寄卡到了吗、路由器发了吗、给的单号查不到、寄回物品收到了吗、迟迟不发想投诉。

## 3. 必查知识

先本流程与全局边界；退货或退款阶段见[07](07_returns_refunds.md)，改地址/暂缓/拦截见[09](09_invoice_order_changes.md)。无需为单纯发货问题查全部型号与灯态。

## 4. 处理流程

### 核验主链

1. **适用场景**：客户问发出、到达或异常。
2. **已知与关键未知**：复用订单卡、商品、补寄/售后记录、客户所述等待时间与旧承诺；不足时只补能定位记录或区分包裹方向的一项。历史卡片、零元金额和旧通知不能证明无效/已发/已到。
3. **本轮动作**：回应当前等待或疑问，当前客服核对对应业务阶段，不向客户发整套物流排查。
4. **客户草稿示例**：“您等了这么久，我先核对这次寄出的安排和当前进度，再告诉您实际情况。”中性咨询不必机械道歉。
5. **客服内部核验**：按下表核实发货约定→实际受理/出库→运单与轨迹→异常处理；已有记录优先复用，有权限才查询，权限不足请负责岗位返回必要结果。
6. **反馈后的分支**：真实阶段确定后给对应进展或下一可执行动作；日期和时效只用经确认适用的信息。
7. **停止排查或交接条件**：状态无权限、记录关联不清、超过适用承诺、轨迹异常或客户投诉等待时，交内部履约/售后/配送负责岗位，不能仅重复“请等待”。
8. **风险与依据**：不承诺48小时、当天发或几日必到；不把历史“联系仓库”当已执行，不说助手已催办或改运单。

### 各场景的核验分支

| 场景与前置识别 | 本轮核验项 | 结果后的动作与交接 |
|---|---|---|
| 购买订单催发 | 对应订单、现货/预售与正式约定、实际出库 | 未超约定反馈真实安排；超过约定找履约核实阻塞与可执行处理。等待时长本身不证明超时 |
| 补寄卡/配件或更换设备 | 对应补寄/售后受理、物品、出库及运单 | 受理不等于已发；关联不明先内部查记录，必要再澄清新购还是更换，不套整机现货规则 |
| 发哪家快递 | 对应渠道/区域配送规则或该单实际承运商 | 未下单说明核实规则，已下单答真实承运商；不能保证所有地区固定一家 |
| 单号查不到 | 历史提供的号、订单关联、实际出库、揽收与查询渠道 | 确认错号才更正；未揽收或查询延迟须有依据，不能先判虚假发货或责怪客户 |
| 物流停滞或未到 | 最近有效轨迹、时间与承运反馈 | 区分未揽收、运输或派送异常，通过有权限岗位跟进；未联系不称已催促 |
| 客户寄回收件 | 寄回物品/用途、运单、仓库或售后实际收件 | 客户派送中不等于已收；物流妥投也未必等于验收/审核。确认用途后转检测或退款阶段 |
| 当前可售或延期安排 | SKU可售/供货及订单约定，修改可行性 | 当前客服核验，不能用旧库存记录承诺；修改转09，权益转08 |

## 5. 标准回答规则

先区分商家寄出与客户寄回，再区分购买、补寄和检测返还。没有实时状态是正常条件，仍能帮助客服核验；不假设仓储或快递接口已接入。路由器、卡片、整机不能混为一项。

## 6. 常见问答

### 客户已经给订单卡，还要订单号吗？

当前客服能用已有记录定位就先核验。脱敏编号无法查实际订单时只补最少定位信息；不能假装占位编号已被查到，也不机械重复索取全部个人信息。

### 历史通知说已发货，可以直接照说吗？

它只证明有一条旧通知。核对同一订单、时间、实际出库与最新轨迹，已发、待揽收、妥投、收件受理是不同状态。

## 7. 复杂场景处理

客户对先前承诺不满时，承接具体等待并核查跟进是否实际发生，交接原承诺与已知现象，不编造新时限。客户同时提退款时确认当前目标，转07；补发与退货期限冲突时并行核验，危险配件先走03保护。

## 8. 需要追问的情况

只补订单/售后定位、包裹方向、物品或核验必须的区域。已有信息不重复问；不询问不影响物流的设备设置。

## 9. 需要转人工的情况

当前客服无权限或需跨岗位协调时找内部履约/售后/配送负责岗位，交接定位、物品方向、客户诉求、已知等待与待核实节点，请返回当前阶段和可执行安排。实际岗位和渠道待业务确认。

## 10. 来源索引

MVP未接入业务数据的能力边界、旧服务边界及开发会话发现的购买/补寄/寄回诉求。聊天中的时效、仓库、承运商和营销承诺未升级为政策。
