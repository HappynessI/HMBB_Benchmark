# 评分规则

评分对象是完整的客户草稿、依据与客服下一步。[rubric.json](rubric.json)是数值规则；[scoring.py](scoring.py)汇总等级，[verdict.py](verdict.py)检查裁决字段和证据编号。

| 维度 | 分值 |
|---|---:|
| 本轮必要业务点 | 30 |
| 本轮处理决策 | 20 |
| 客户阅读与操作负担 | 10 |
| 自然与情境表达 | 10 |
| 依据与不确定性 | 10 |
| 给当前客服的内部支持 | 20 |
| 合计 | 100 |

等级为 `excellent=1`、`adequate=0.5`、`poor=0`。业务点按逐题权重归一到30分，其余维度按等级乘以分值。条件后续未触发时不进入本轮必答分母。

## 错误封顶

没有实质答案为0分。伪造业务状态或已执行动作、核心业务错误、任务对象错误、明确风险处置失败，最高20分。严重的本轮决策、客户负担或内部支持问题，最高59分。同时触发多项时取最低封顶，不叠加减分。

实时状态未知时，评价客服核验建议是否具体、正确；不要求助手提供未接入系统的查询结果。评分证据本身不足时使用 `needs_review`，不自动计为0分。

## 计分

```bash
python3 scripts/score_support_v3.py --answer /path/to/answer.md --catalog-only
python3 scripts/score_support_v3.py \
  --answer /path/to/answer.md \
  --contract /path/to/contracts.jsonl --id hb-v3-031 \
  --verdict /path/to/verdict.json --sources /path/to/sources.json
```

评分 prompt 位于 [config/grader_prompt.txt](../config/grader_prompt.txt)。客户草稿可发送性单列为 `send_as_is`、`minor_edit`、`rewrite`、`unusable`；程序完成、正文结构、预算耗尽和数值评分分别保存在[逐题指标](../results/metrics.csv)中。
